## Commands

**IMPORTANT**: Use `bun` as the package manager for all development commands (not npm or yarn).

### Development
- `bun run dev` - Start development server with Turbopack on localhost:3000
- `bun run build` - Build the application for production
- `bun start` - Run the production server
- `bun run lint` - Run ESLint on the codebase
- `bun install` - Install dependencies

### Database (Drizzle ORM)
- Database schema is defined in `lib/db/schema.ts`
- `bunx drizzle-kit generate` - Generate migration files from schema changes
- `bunx drizzle-kit migrate` - Apply migrations to database
- `bunx drizzle-kit push` - Push schema changes directly to database (development)
- `bunx drizzle-kit studio` - Open Drizzle Studio GUI for database management
- Requires `DATABASE_URL` environment variable (Neon PostgreSQL)

## Architecture

### Stack
- **Framework**: Next.js 15.4.6 with App Router
- **UI Components**: shadcn/ui (46 pre-built components based on Radix UI)
- **Styling**: Tailwind CSS v4 with CSS variables
- **Language**: TypeScript with strict mode
- **React**: Version 19.1.0
- **Database**: Drizzle ORM with Neon PostgreSQL (serverless)
- **Package Manager**: Bun (primary, bun.lock present)

### Project Structure
- `/app` - App Router directory
  - `layout.tsx` - Root layout with Geist fonts (no theme provider by default)
  - `page.tsx` - Homepage component
  - `globals.css` - Global styles with Tailwind imports and CSS variables
  - `error.tsx`, `global-error.tsx`, `not-found.tsx` - Error handling pages
- `/components` - Component library
  - `/ui` - shadcn/ui components (accordion, alert, button, card, dialog, form, etc.)
  - `error-boundary.tsx` - Custom React error boundary with circuit breaker pattern
- `/lib` - Utilities
  - `utils.ts` - Contains `cn()` for className merging with clsx and tailwind-merge
  - `/db/schema.ts` - Drizzle ORM schema definitions
- `/hooks` - Custom React hooks
  - `use-mobile.ts` - Mobile detection hook
- `/public` - Static assets
- `/drizzle` - Database migration files (generated by drizzle-kit)

### Key Configuration
- **Path Alias**: `@/*` maps to `./*` in TypeScript (also configured in components.json)
- **shadcn/ui Style**: "new-york" variant with CSS variables, neutral base color
- **Turbopack**: Enabled for faster development builds
- **ESLint**: Configured with Next.js core-web-vitals and TypeScript rules
- **Database**: Drizzle config at `drizzle.config.ts`, PostgreSQL dialect for Neon
- **Node.js**: Minimum version >=20.0.0

### Component Library
This project includes a complete shadcn/ui component library with:
- Form components with React Hook Form and Zod validation
- Data display (tables, cards, badges)
- Navigation (tabs, breadcrumbs, navigation-menu)
- Feedback (alerts, toasts via sonner, progress indicators)
- Overlays (dialogs, sheets, tooltips, popovers)
- Data input (all form controls, date-picker, OTP input)
- Layout (accordion, collapsible, resizable-panels, scroll-area)

### Development Workflow
1. Components are in `/components/ui/` - use existing components before creating new ones
2. Use the `cn()` utility from `@/lib/utils` for conditional class names
3. Theme switching: next-themes is available as dependency but not configured in layout by default
4. Forms use React Hook Form with Zod schemas for validation
5. Icons are from lucide-react
6. Charts and data visualization with recharts
7. Date utilities from date-fns
8. Database: Define schema in `lib/db/schema.ts`, then run `bunx drizzle-kit generate` and `bunx drizzle-kit migrate`

### Error Handling
- Custom `ErrorBoundary` component available at `/components/error-boundary.tsx`
- Supports circuit breaker pattern (auto-reset after 3 errors)
- Configurable levels: 'page', 'section', or 'component'
- Shows detailed error info in development, user-friendly messages in production
- Usage: Wrap components with `<ErrorBoundary level="page">` or use `withErrorBoundary()` HOC
- Next.js error pages: `error.tsx`, `global-error.tsx`, `not-found.tsx` in `/app`

### Database (Drizzle ORM)
- ORM: Drizzle with @neondatabase/serverless driver
- Schema: Define tables in `lib/db/schema.ts` using Drizzle syntax
- Migrations: Generated in `/drizzle` directory
- Configuration: `drizzle.config.ts` with verbose and strict mode enabled
- Environment: Requires `DATABASE_URL` env var for Neon PostgreSQL connection
